## Test architecture

Use TypeScript tests with fake timers, local HTTP servers, real temporary SQLite databases and child-process crash injection. Vitest is a proposed runner; pin a Node-compatible version during implementation. No framework currently exists in this repository. Do not replace persistence integration tests with mocked SQL. Use synthetic messages/tokens in CI. No real tenant credentials, profiles, private message fixtures or unredacted traces in artifacts.

## Planned execution and coverage

```text
config/credential check
  +-- valid -> login or load credential
  +-- invalid config, unsafe perms/symlink -> fail before network
login/identity [E2E]
  +-- correct account -> ready
  +-- mismatch, cancelled login, expired token -> needs-login
discovery/activation/pages
  +-- baseline saved -> new arrivals eligible, older ignored
  +-- interrupted baseline -> same cutoff on restart
  +-- overlapping/equal-time records -> unique IDs retained
  +-- bad URL, malformed record, missing boundary -> pause chat
policy/normalization
  +-- allowed DM / allowed triggered group -> enqueue
  +-- denied, self, system, edited/deleted, untriggered -> no invocation
  +-- unknown/malformed event -> no cursor advance; diagnostic
enqueue/claim [integration]
  +-- atomic cursor+jobs -> ordered durable work
  +-- duplicate / full queue / DB failure -> no lost cursor/work
invoke OpenClaw [integration/E2E]
  +-- accepted completion -> save response
  +-- definite refusal -> structured failed/retryable outcome
  +-- submitted timeout/crash -> uncertain, no auto-reinvoke
split/send [integration/E2E]
  +-- each confirmed part -> saved ID, next part
  +-- ambiguous result/crash -> uncertain, no auto-resend
restart/operator recovery [integration/E2E]
  +-- response_ready -> delivery only, no repeated agent run
  +-- invoking/sending -> uncertain and chat paused
  +-- mark complete/cancel/explicit retry -> documented next state
cleanup/status/package
  +-- expired payload -> purge content, preserve metadata
  +-- diagnostic -> actionable, no credentials/bodies
  +-- packaged archive -> allowlisted build/docs only
```

Every listed branch is a required assertion group; none has been implemented or run. Actual branch coverage must be measured after implementation, with a goal of 100% for authored policy/state/recovery logic; dependency internals are not claimed covered. The ten high-level flow areas in the review map currently have zero executable coverage.

## Real user flows / live acceptance

1. Operator obtains private access to the EC2 browser and signs in as the configured account. Confirm authenticated account using a service-backed identity lookup, not only a display-name or decoded JWT claim. Check file permissions and persistence after reboot under the intended service user.
2. Resolve the human-authorized test recipient to a unique stable identity; stop if resolution is ambiguous. Send a clearly labeled test message only to that recipient. Recipient details stay in local configuration, not public docs.
3. Human sends two DM turns: confirm correct replies and same session. Confirm a second conversation has a separate session.
4. In a designated test group with permission to test, confirm prefix and supported mention behavior, no answer to untriggered traffic, allowed sender filtering and correct destination. No group has yet been designated; DM test authorization does not authorize arbitrary group sends.
5. Stop/restart the bridge mid-flight with controlled test work. Confirm visible paused/uncertain status and operator recovery. Do not use sensitive tool side effects in the test agent.
6. Run beyond the candidate cache's 23-hour window and exercise real invalid-session behavior. Record whether browser reuse succeeds or operator reauthentication is required; no indefinite-renewal claim from a short run.
7. On OpenClaw 2026.9.6, verify endpoint enablement, explicit dedicated agent target, stable user session behavior and suitable tool/memory boundaries. Gateway stays on loopback/private ingress.

Live tests require host access and interactive sign-in, which have not occurred. Credentials must be entered through the sign-in flow, never in chat or committed fixtures.

## Failure modes and user-visible behavior

| Path | Production failure | Test above | Handling / visible outcome |
|---|---|---|---|
| Config/storage | Wrong permissions or corrupt cache | credentials/config | Startup refuses; diagnostic explains repair |
| Login | Expiry or account switch | auth/live | needs-login; pending work preserved |
| Paging | Missing boundary, malformed page | ingestion/teams-contract | Chat pauses; cursor preserved |
| Policy | Unexpected event/mention shape | policy/content | Ignore known unsupported events; malformed records pause |
| Enqueue | Disk full or transaction interruption | store | No cursor advance; local storage-failure status |
| Invocation | Request accepted but response lost | openclaw/recovery | uncertain; chat pauses; no auto-reinvoke |
| Delivery | Reply accepted but response lost | delivery/recovery | uncertain; no auto-resend |
| Restart | Worker dies after external side effect | recovery | Durable state exposes uncertainty |
| Cleanup | Payload expires before resolution | retention | Metadata kept; expired job requires resolution |
| CLI/package | Broken installed CLI or raw exception leak | cli/package | CI fails release; sanitized runtime error |

Each path has planned tests and an explicit local error/status behavior. There are no known silent failures left unspecified in this matrix; this is a planning result, not evidence that runtime handling exists.

## LLM evaluation boundary

This review does not change agent system prompts or model selection. Deterministic tests must verify the bridge cannot interpret model output as a destination, permission change or command, and must preserve sender text as untrusted content. Live acceptance checks conversation continuity and sender attribution; it does not claim model-quality evaluation or tool authorization from prompt text.

## Implementation evidence (2026-10-03)

All 30 implementation tests pass locally and on the target Ubuntu / Node 24.21.0 host. Coverage includes protected-file validation, HTTP deadlines and redirect rejection, throttling, SQLite transaction rollback, cursor overlap and history gaps, policy revocation, queue fairness, reply-part recovery, retention, actual killed worker processes, and a complete runner process against local HTTP fixtures. The bounded tenant experiment confirmed fresh DM and prefixed group round trips and separate OpenClaw sessions. Persistent services delivered two fresh tenant turns and recovered after both dedicated services restarted; both remained sent without additional queue entries. Overnight operation, host reboot, real mention metadata and reauthentication remain separate live checks. The earlier planning statements describe the state at engineering review, before deployment.
